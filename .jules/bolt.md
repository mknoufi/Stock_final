## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. **Learning:** In highly trafficked backend sync endpoints (`sync_batch` and `_process_legacy_operations`), performing iterative `find_one()` lookups to check idempotency in a large loop causes significant N+1 query latency and connection overhead to MongoDB via the Motor driver.
**Action:** Always pre-fetch existing records required for validation into an in-memory `set` outside the loop using an `$in` query with strict field projections (e.g. `{"_id": 1, "operation_id": 1}`). During iteration, add processed items back into the local set to maintain intra-batch constraints without round trips.
