## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. **Learning:** The `dashboard_analytics_api.py` contained significant N+1 database queries across `_breakdown_by_location`, `_breakdown_by_category`, `_breakdown_by_session`, and `_breakdown_by_date`. Within loops over grouped entities (locations, categories, sessions, dates), it repeatedly called `db.erp_items.find()` or `db.count_lines.find()`. By pre-fetching `count_lines` for all relevant entities in a single batched query using the `$in` or `$gte`/`$lte` operators, and subsequently collecting all unique `item_codes` to fetch prices from `erp_items` in another single query, we replace O(N) database round-trips with O(1) operations.
**Action:** When aggregating or grouping data to calculate metrics across entities, always collect the necessary IDs/keys first. Then perform a single bulk query using `$in` to fetch the related data, map it in-memory, and apply the calculations inside the loop using the cached map to prevent N+1 performance degradation.
