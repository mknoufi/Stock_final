## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. **Learning:** Sequential, full-document database queries via motor cursors (`db.collection.find({}).to_list(None)`) cause enormous memory overhead and I/O latency when querying large collections like `erp_items` in analytical endpoints.
**Action:** When aggregating multiple large datasets in a single request (e.g., dashboards), aggressively apply field projections (`{"item_code": 1, "stock_qty": 1, "_id": 0}`) and batch independent cursor resolutions using `await asyncio.gather(...)` to execute them concurrently, drastically cutting response time and footprint.
