## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. **Learning:** In the Python backend, constructing MongoDB queries using `$in` with large, non-deduplicated arrays (e.g., from raw mapping of relationships) can cause significant memory bloat, unnecessary serialization overhead, and slow database execution. Even if MongoDB internally optimizes `$in`, the sheer size of the BSON payload transmitted over the network is detrimental.
**Action:** Always wrap list comprehensions or mapped arrays destined for `$in` queries with `list(set(...))` to ensure uniqueness and minimize payload size, particularly in analytics or batch-processing endpoints.
