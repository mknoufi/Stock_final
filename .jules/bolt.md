## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. **Learning:** In MongoDB `update_many` operations, `modified_count` only reflects documents that actually changed state. If an update is idempotent (e.g., setting `is_active` to `True` for a user already active), `modified_count` will not increment for that document. If you're replacing a loop that counts every processed ID with a bulk operation, you must use the length of the filtered input array (or `matched_count`) rather than `modified_count` to calculate the total processed items, otherwise the API will underreport successes and potentially break frontend logic.
**Action:** Always consider the difference between `matched_count` and `modified_count` when calculating success metrics for bulk update operations. Use the length of the validated input array for aggregate success counts in idempotent bulk operations.
