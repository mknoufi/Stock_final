## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. Ensure you calculate an accurate `estimatedItemSize` by inspecting the item's layout and styles (padding, margins, font sizes) rather than guessing.
## 2024-06-12 - [Dashboard Analytics N+1 Queries & Memory Optimization]
**Learning:** In analytical endpoints (like `dashboard_analytics_api.py`), iteratively fetching related entities inside loops causes severe N+1 query problems. Additionally, loading the entire `erp_items` collection into memory just to calculate sum values can cause major memory spikes.
**Action:** Always batch fetch related records outside of loops using `$in` and group them in-memory via Python dictionaries for O(1) lookups. When aggregate calculations are needed on large collections but cannot be executed in the database, minimize memory footprint by using explicit field projection in the MongoDB query (e.g., `db.erp_items.find({}, {"item_code": 1, "stock_qty": 1, "mrp": 1, ...})`) rather than fetching the full documents.
