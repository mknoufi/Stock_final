## 2024-05-24 - [List Rendering Optimization in React Native]
**Learning:** React Native's standard `FlatList` can suffer significant frame drops and memory issues when rendering long, complex items or paginated lists with infinite scrolling (like search results). The `VirtualList` component (which wraps `@shopify/flash-list`) is vastly superior for these use cases but requires a precisely calculated `estimatedItemSize` to function optimally.
**Action:** When working with potentially long lists in this codebase (especially in search or data tables), always prefer `VirtualList` over `FlatList`. Ensure you calculate an accurate `estimatedItemSize` by inspecting the item's layout and styles (padding, margins, font sizes) rather than guessing.
## 2024-06-30 - N+1 Query Anti-Pattern in Bulk Reads
**Learning:** In MongoDB aggregation and bulk read operations within the Python backend, looping over `find_one()` (or `find()`) sequentially for lists of IDs leads to a classic N+1 performance bottleneck. This pattern occurs in unoptimized legacy endpoints (like `bulk_export_sessions`).
**Action:** When refactoring or encountering bulk loops in Python endpoints, replace sequential `find_one()` calls with a single bulk fetch using the `$in` operator. Ensure you deduplicate input arrays passed to `$in` using a set comprehension (e.g., `list({sid for sid in session_ids if sid})`) to minimize MongoDB execution planning time, network payload size, and intermediate Python memory overhead. For async Motor operations, always await the cursor using `to_list(length=None)`.
